# AGENTS.md — Инструкции для ИИ-разработчиков (Gemini & Codex)

Этот файл является единым источником правил для ИИ-агентов (**Gemini**, **Codex** и др.), ведущих разработку прототипа **AI-buddy** для хакатона **Avito Start (Hack&Change 2026)**.

---

## 1. Контекст проекта и жёсткие требования жюри

Мы создаём **AI-buddy** — ИИ-наставника для адаптации стажёров в командах Авито.
Любой код, который ты пишешь, должен строго соответствовать следующим критериям оценки из кейса:

1. **Спецификационная разработка (SDD / OpenSpec):**
   - Все контракты лежат в папке `specs/`:
     - `specs/agent-sdd.yaml` — SDD-спецификация поведения агента, системных промптов, guardrails и сценариев.
     - `specs/mcp-tools.json` — схемы MCP-инструментов и корпоративных сервисов Авито.
     - `specs/openapi.yaml` — REST API контракт между Backend и Frontend.
   - **Правило синхронизации:** нельзя самовольно менять формат JSON-полей API или сигнатуры MCP-инструментов в коде без обновления `specs/`.
2. **Покрытие тестами `>80%` (Жёсткое ограничение слайда 12, п. 07–08):**
   - Покрытие строк прикладного кода автоматизированными тестами должно **превышать 80%** (не считая внешних зависимостей, сгенерированного кода и самих тестов).
   - Каждая новая фича в `backend/` (`Go`) или `frontend/` (`React/TS`) сопровождается unit/интеграционными тестами в том же коммите/задаче.
3. **Быстродействие `<1 с` и неблокирующий UI (Слайд 12, п. 09–10):**
   - Локальные операции (переключение ролей, получение/отметка шагов чек-листа, просмотр заявок и метрик) обязаны отвечать быстрее **1 секунды** (целевой ориентир на бэкенде `<50 мс`).
   - Обращения к внешнему LLM (**OpenRouter**) и корпоративным сервисам не должны блокировать интерфейс: обязательно показывать статус ожидания (step-by-step индикатор работы агента) и корректно обрабатывать сбои.
4. **Безопасность и ролевая модель RBAC (Слайд 12, п. 04–06):**
   - В системе действуют 3 роли: `intern` (Стажёр), `mentor` (Наставник / Buddy), `manager` (Руководитель команды).
   - AI-buddy обязан проверять права пользователя **до** выдачи документов из базы знаний и **до** вызова любого MCP-инструмента. Недоступные стажёру сведения (зарплатные данные, закрытые HR-оценки) и операции (например, доступ `prod-db-admin` или аппрув чужого отгула) должны блокироваться на уровне кода (`internal/rbac`), а не только промпта.
5. **Безотказность на проверке экспертами жюри (Слайд 9 и 13 «Допуск»):**
   - Основной LLM-провайдер: **OpenRouter** (`OPENROUTER_API_KEY`, `OPENROUTER_BASE_URL`, `OPENROUTER_MODEL`).
   - Если `OPENROUTER_API_KEY` не задан, истёк или внешний API недоступен в закрытом контуре проверяющего, бэкенд **автоматически** использует детерминированный `Smart Fallback Engine`, который полноценно проводит эксперта по всем 3 сценариям с вызовом реальных MCP-инструментов и сохранением состояния в БД.

## 2. Технологический стек и версии окружения

Используй актуальные версии инструментов, установленные в окружении:

- **Backend (`backend/`):**
  - Язык: **`Go 1.27.3`** (`go1.27.3`)
  - Роутер: `github.com/go-chi/chi/v5` (или стандартный `net/http` с роутингом Go 1.22+)
  - Хранилища: `PostgreSQL 16` + `Redis 7` (с поддержкой быстрого in-memory стора для изолированных unit-тестов и мгновенного локального старта)
  - Протокол инструментов агента: **MCP (Model Context Protocol)** в `backend/internal/mcp`
- **Frontend (`frontend/`):**
  - Среда: **`Node.js v26.13.0`**, `npm 12.2.2`
  - Фреймворк: **`React 19` + `TypeScript` + `Vite`**
  - Стейт и данные (стек Авито со слайда 11): **`TanStack Query` (`@tanstack/react-query`)**, **`Zustand`**, **`Zod`**
  - Стилизация: **`Tailwind CSS` + `Lucide Icons`** в палитре дизайн-системы **Avito Start**
  - Тестирование: **`Vitest` + `@testing-library/react` + `@vitest/coverage-v8`**
- **Инфраструктура:**
  - `Docker` (`29.9.3`) и `docker compose`
  - `Makefile` для единого запуска тестов и генерации отчёта о покрытии

## 3. Разделение зон ответственности между разработчиками (Gemini vs Codex)

Чтобы два разработчика с ИИ-агентами работали параллельно без конфликтов слияния (merge conflicts), репозиторий разделён по директориям:

| Зона / Папка | Ответственный агент / разработчик | Правило работы |
| :--- | :--- | :--- |
| `docs/`, `specs/`, `data/` | Общий контракт (инициализируется первым) | Изменения в `specs/` согласуются обоими разработчиками |
| `backend/` | **Трек 1 (Backend Developer — Gemini / Codex)** | Пишет код только внутри `backend/`, опираясь на `specs/openapi.yaml`, `specs/mcp-tools.json`, `specs/agent-sdd.yaml` |
| `frontend/` | **Трек 2 (Frontend Developer — Codex / Gemini)** | Пишет код только внутри `frontend/`, строго по схемам из `specs/openapi.yaml` |
| `docker-compose.yml`, `Makefile`, `README.md` | Стыковка на интеграционном шаге | Проверяется совместным запуском `make test` и `make coverage` |

## 4. Команды проверки качества (выполнять перед каждым коммитом)

```bash
# 1. Проверка и тесты Backend (Go 1.27.3) с отчётом покрытия (>80%)
cd backend && go test -v -race -coverprofile=coverage.out ./... && go tool cover -func=coverage.out

# 2. Проверка типов и тесты Frontend (React/TS) с отчётом покрытия (>80%)
cd frontend && npm run typecheck && npm run test:coverage

# 3. Полная сборка и проверка всего проекта из корня
make coverage
```

## 5. Правила оформления кода и данных

1. **Никаких реальных персональных данных и секретов в коде:** используй только синтетических сотрудников (например, *Алексей Смирнов — Backend Go Intern*, *Мария Козлова — Senior Go Developer / Buddy*, *Дмитрий Волков — Engineering Manager*).
2. **Явная маркировка тестовых инструкций:** в UI и базе знаний обязательно указывать, что регламенты и сервисы (`Avito Absence Mock`, `Avito Access/IDM Mock`) являются синтетическими имитациями для прототипа хакатона (требование слайда 12, п. 02–03).
3. **Чистая архитектура для тестируемости:** не зашивай вызовы внешних сетевых сервисов напрямую в HTTP-хендлеры — используй интерфейсы Go (`LLMClient`, `Repository`, `MCPExecutor`), чтобы unit-тесты работали за миллисекунды и стабильно давали `>85%` покрытия.
