## 💡 О проекте и бизнес-эффект

По оценке команды Авито (слайд 5), занятость наставника (buddy) составляет **40–48 часов** (за 6 мес) и **55–65 часов** (за 9 мес). До 50% этого времени уходит на повторяющиеся бытовые и процессные вопросы.

**AI-buddy** — это интеллектуальный наставник нового поколения, который:
- Сокращает рутинную нагрузку на buddy на **40–45%** (экономит **18–22 часа** работы Senior/Middle инженера на каждого стажёра).
- Ускоряет `Time-to-First-PR` с 12 до **7 рабочих дней**.
- **Выполняет реальные действия** через корпоративные сервисы Авито (протокол **MCP**): оформление учебных отгулов, запрос доступов в IDM, синхронизация чек-листа адаптации.
- **Жёстко соблюдает безопасность (RBAC):** блокирует попытки запроса привилегированных ресурсов (`prod-billing-db`) и закрытых HR/зарплатных данных.
- **Не заменяет содержательную работу наставника:** при архитектурных вопросах автоматически формирует структурированную повестку для 15-минутного синка 1:1.

## 🛠 Архитектура и стек технологий (Авито)

Архитектура прототипа на 100% соответствует технологическому ландшафту Авито (слайд 11):

| Слой | Технологии | Назначение |
| :--- | :--- | :--- |
| **Backend** | **Go 1.27.3** (`net/http` pattern routing) | Высокая производительность, локальный отклик `<10 мс` (требование кейса `<1 с`), чистая модульная архитектура (`internal/rbac`, `internal/mcp`, `internal/rag`, `internal/ai`). |
| **Frontend** | **React 19 + TypeScript + Vite** | Дизайн-система Avito Start, стилизация на **Tailwind CSS**, иконки **Lucide**. |
| **Стейт и данные** | **TanStack Query + Zustand + Zod** | Рекомендованный стек Авито: неблокирующий UI при обращении к LLM, управление ролями и валидация. |
| **Протокол агента** | **Model Context Protocol (MCP)** | Подключение сервисов `Avito Absence`, `Avito Access / IDM`, `Mentor 1:1 Sync` и `Clickstream`. |
| **Хранилища** | **PostgreSQL 16 + Redis 7** | Персистентность заявок и быстрый кэш сессий (с поддержкой in-memory режима для мгновенного старта). |
| **LLM Runtime** | **OpenRouter API** + **Smart Deterministic Fallback** | Автоматический двухконтурный режим: работает с ключом OpenRouter или полностью автономно без ключа (100% надёжность при проверке экспертами). |

## 🚀 Быстрый запуск (Docker Compose за 1 команду)

### Способ 1. Запуск через Docker Compose (Рекомендуемый для жюри)

```bash
# 1. Склонируйте репозиторий
git clone <repo-url> && cd ai-buddy

# 2. Создайте файл конфигурации (при необходимости укажите ключ OpenRouter)
cp .env.example .env

# 3. Запустите весь стек одной командой
docker compose up --build
```

После старта:
- **Веб-интерфейс прототипа:** Откройте в браузере [http://localhost:5173](http://localhost:5173) (или порт 80 при сборке Nginx)
- **REST API Backend:** [http://localhost:8080/api/v1/health](http://localhost:8080/api/v1/health)

> **Обратите внимание:** Если переменная `OPENROUTER_API_KEY` в `.env` пустая, автоматически активируется встроенный **Smart SDD Fallback Engine**. Эксперт сможет полноценно пройти все 3 сценария от начала до конца, увидеть вызовы MCP-инструментов и сохранение в БД без предоставления собственного API-ключа!

### Способ 2. Локальный запуск разработчика

```bash
# Терминал 1: Go Backend (Go 1.27.3)
cd backend && go run ./cmd/server

# Терминал 2: React Frontend (Node 26+)
cd frontend && npm install && npm run dev
```

## 👥 Тестовые учётные записи и сценарии проверки жюри

В шапке интерфейса размещён **демо-переключатель ролей в 1 клик**:

| Роль | Тестовый сотрудник | Описание и доступные действия |
| :--- | :--- | :--- |
| **Стажёр (Intern)** | **Алексей Смирнов** (Backend Go Intern, Авито Доставка) | Доступен онбординг, чек-лист, чат с AI-buddy, создание заявок на отгул и доступы. Закрыты: прод-БД, зарплаты, согласование заявок. |
| **Наставник (Buddy)** | **Мария Козлова** (Senior Go Developer, Авито Доставка) | Доступны: панель наставника, согласование/отклонение заявок стажёра, просмотр повесток 1:1, live-метрики сэкономленного времени. |
| **Руководитель (Manager)**| **Дмитрий Волков** (Engineering Manager, Авито Доставка) | Полный доступ: финальное согласование отгулов, бюджетные регламенты, аналитика подразделения. |

### Порядок проверки 3 сценариев из кейса:

1. **Сценарий 1 («Доступы в IDM и окружение»):**
   - Нажмите быстрый пресет: *«🚀 Сценарий 1: Доступы в IDM»*.
   - AI-buddy объяснит регламент по `AvitoTech Playbook`, вызовет MCP-инструмент `request_service_access`, создаст одобренную заявку в **Avito Access / IDM** и автоматически отметит шаг чек-листа.
   - **Проверка RBAC (Негативный кейс):** Нажмите пресет *«🔒 Проверка RBAC: Прод-БД»*. AI-buddy и модуль `internal/rbac` заблокируют запрос к `prod-billing-db` с наглядным предупреждением безопасности.
2. **Сценарий 2 («Оформление отгула на экзамен» — кейс со слайда 4):**
   - Нажмите пресет: *«📝 Сценарий 2: Отгул на экзамен»*.
   - AI-buddy сформирует черновик заявки (**Human-in-the-Loop Action Card**).
   - Нажмите в карточке **«Подтвердить и отправить»**.
   - Переключите роль в шапке на **«Наставник (Мария)»** — заявка появится во входящих с кнопками *«Согласовать»* и *«Отклонить»*.
3. **Сценарий 3 («Первая задача и повестка к 1:1 с наставником» — слайд 5):**
   - Нажмите пресет: *«🤝 Сценарий 3: Повестка к 1:1»*.
   - AI-buddy вызовет MCP-инструмент `prepare_mentor_1on1_summary`, зафиксирует выполненную работу и выделит 3 точечных архитектурных вопроса по кэшированию в Redis, сэкономив до 45 минут времени наставника.

## 📄 Спецификации SDD и MCP (Обязательное требование слайдов 8 и 11)

- **`specs/agent-sdd.yaml`** — формальная SDD-спецификация поведения агента (OpenSpec / spec-kit), системные промпты, guardrails и детерминированные графы.
- **`specs/mcp-tools.json`** — JSON Schema всех 6 MCP-инструментов (`search_knowledge_base`, `get_onboarding_status`, `complete_checklist_item`, `request_service_access`, `create_absence_request`, `prepare_mentor_1on1_summary`, `review_corporate_request`).
- **`specs/openapi.yaml`** — REST API контракт между бэкендом и фронтендом.
- **`data/knowledge/avito_playbook_seed.json`** — синтетическая база знаний на базе открытого `AvitoTech Playbook` с разметкой прав доступа (`intern`, `mentor_only`, `manager_only`).
